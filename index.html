Четыре файла вместо одного промпта

Промпт умирает вместе с чатом. Rule, skill, RAG и ADR лежат в git — следующий агент читает их, а не вашу память. Один файл на 500 строк — антипаттерн.

ПДД: лимиты и defaults на каждый чат.

.clinerules/ · AGENTS.md
Авто (toggle). 10–80 строк.

2–4 файла на задачу. Один id = файл.

Как агент это видит

В IDE rule включается сам. Skill читают фразой «прочитай SKILL.md». RAG — 2–4 пути, которые назвал skill. ADR — цитата «почему так».

Наращивание: skill → + rule → + RAG (занятие 3) → + ADR (занятие 4). Листы 10–13 — тот же сюжет с выключенными слоями. Живой login: 30–35 (Context — сцена, не слой). main — логин / items, без note. develop — заметка влита. Ярусы takeaway: unit → integration → component → api → ui → e2e → manual. Chrome на стабе — ui, не e2e.

Пак: docs/agent-skills/PACK.md Rule 01: один task test + tags · @Tag("smoke") — prod slice (ADR 005) занятия 2–4

01 · skill

Skill — маршрутный лист на одну задачу

Не энциклопедия и не ПДД. Skill отвечает: когда вызывать, какие шаги, когда считать готовым. Имя: qa-<глагол>-<объект>. Раннер CI и Sonar — не имя skill, а RAG.

docs/agent-skills/qa-write-test/SKILL.md

Каркас

  • When — триггеры («напиши e2e», «покрой API»)
  • Do not — CSS в тесте, ChromeDriver (commit / URL — rule)
  • Steps — слой → стенды → PO → прогон
  • DoD — чеклист, не «ну вроде ок»
  • RAG (2–4 id) — факты рядом, не внутри

Промпт

Rules ON. Прочитай docs/agent-skills/qa-write-test/SKILL.md и чанки po-locators, po-step, test-negative, cfg-stands. Добавь автотест на неуспешный логин с неправильным паролем. Укажи pipeline/stage/prod.

Это skill

  • Один глагол, один объект
  • Живые команды takeaway
  • Один Cline task = один skill

Не skill

  • GitHub vs Jenkins — чанки ci-*
  • TMS / AllureId — tms-meta
  • JaCoCo / Sonar — quality-gates
  • Хост (DNS) ≠ стенд (qa-run-stand)

02 · rule

Rule — ПДД, которые всегда в силе

Rule не учит «как пройти маршрут». Он говорит: этого не делать / вот default. Короткий, always-on, срабатывает в каждом новом task, если toggle включён.

.clinerules/01-qa-java-gradle.md

## E2e slice
cd tests/java/tests-java-gradle-junit5-allure3-selenide
./gradlew test -Denv=ci -DincludeTags=e2e -DexcludeTags=screenshot

## Запреты
- Не git commit без явной просьбы
- Не удалять allure-results
- Не ./gradlew test без -DincludeTags «на smoke»

Загрузка

.clinerules/*.md и AGENTS.md — авто, тумблер Rules в Cline.

Сменили rule или skill → новый task. Старый чат старый контекст не подхватит.

Размер

10–80 строк. Если появились шаги и DoD — это уже skill: вынесите.

03 · rag

RAG — факт, не маршрут

Skill говорит как идти. RAG — карточка с полки: команда, селектор, стенд, контракт. Агент читает 2–4 файла, которые назвал skill. Не всю папку, не monorepo из ~96 чанков.

простой мир · библиотека

Человек: «Доклад про чайник»
        ↓
Skill → тема → 2–4 карточки → черновик
RAG   → кнопка слева · 100 °C · 4 этаж

«Прочитай весь стеллаж» → 7b тонет
и ставит $("input") в *Tests.

Одна машина, разные действия. Не «skill DeLonghi» vs «skill Nespresso».

04 · adr

ADR — почему выбрали A, а не B

Пишем, когда решение дорого откатывать: все этажи закупили один тип чайника. Не пишем: «сегодня Earl Grey» (это промпт) и «поставь JDK 21» (это RAG / rule).

каркас · ≤ 40 строк · docs/adr/NNN-*.md

# ADR NNN: короткий заголовок-решение
Статус: предложено | принято | отменено
Контекст: какая развилка (A vs B).
Решение: что выбрали (1–5 пунктов).
Последствия: что теперь нельзя / что стало проще.
RAG: id чанков, которые держат «как», не «почему».

Чайник

Электрический, не самовар: скорость важнее ритуала. Без ADR стажёр каждый раз спорит «а давайте самовар».

Автотест на логин

401 JSON — слой api, не новый e2e-клик. Это ADR 009. Факт селектора — RAG, не ADR.

005 · screenshot — slice, не слой

Хочется «ярус скриншотов». Пиксельный diff — тот же браузерный сценарий, другой отбор.

  • chrome PNG → @Layer("ui"); welcome после логина → @Layer("e2e")
  • Отбор: @Tag("screenshot") + job ui-tests / e2e-tests
  • @Tag("smoke") — тоже slice, не ярус. Mock env — стенд яруса ui, не slice

006 · одна заметка, HTTP как RFC

Продукт: одна заметка на пользователя, /api/note. Глаголы — как в RFC, таблица статусов — RAG crud-http.

Номер 006 — только пак takeaway. Не путать с monorepo ADR 006 (allurerc).

DoЯрус vs slice (005) · Rest Assured vs e2e на 401 (009) · DS header не форк (008). URL из properties — rule, не ADR.
Don'tДублировать skill внутри ADR. Не писать ADR на каждый новый тест. Не менять таблицу @Layer без ADR.
Чанк «когда»: rag/adr-when.md · stub: _templates/adr-stub.md Канон login: docs/adr/009-login-401-is-api.md · slice: 005-screenshot-not-layer.md занятие 4

21 · login · skill

Skill: маршрутный лист vs «просто напиши тест»

Промпт тот же. Без skill агент изобретает драйвер и селекторы. Со skill qa-write-test — слой, PO, один метод, изолированный прогон.

без skill

@Test
void testWrongPassword() {
  WebDriver d = new ChromeDriver();          // свой драйвер
  d.findElement(By.cssSelector("input"))     // CSS в *Tests
      .sendKeys("user1");
  d.findElement(By.cssSelector("input[type=password]"))
      .sendKeys("wrong");
  d.findElement(By.cssSelector("button")).click();
  assertEquals("error",
      d.findElement(By.className("err")).getText());
}

./gradlew test          // нет -Dtest=Class#method

со skill qa-write-test

@Layer("e2e") @Epic("Authentication") @Feature("Login")
class LoginTests extends TestBase {

  @Test @Tag("e2e") @Tag("negative")
  @DisplayName("Wrong password shows readable error")
  void shouldShowErrorWhenPasswordIsWrong() {
    loginPage.openPage()
            .typeUsername("user1")
            .typePassword("wrongpassword")
            .submitExpectingError()
            .shouldHaveErrorMessage(
                "Wrong login or password");
  }
}

cd tests/java/tests-java-gradle-junit5-allure3-selenide
./gradlew test -Denv=ci -DincludeTags=e2e \
  -Dtest=LoginTests#shouldShowErrorWhenPasswordIsWrong
// слой e2e · стенды ci/stage/prod · exit code
Без skill теряетWhen / шаги / DoD. Нет запрета на CSS в тесте и на новый ChromeDriver. Нет ответа «какой слой, какие стенды». URL в Java и commit — лист 22.
Skill заставляетПрочитать SKILL.md → один @Layer → расширить LoginPage, не класть локатор в тест → прогон -Dtest=Class#method → чеклист DoD.
Сценарий — промпт с листа 20. Skill включают фразой «прочитай SKILL.md» Канон: LoginTests#shouldShowErrorWhenPasswordIsWrong пример · skill

Rule: ПДД, даже если skill уже прочитан

Skill знает как написать метод. Rule не даёт выехать за лимиты: не весь suite, не localhost в Java, не commit без OK. Это always-on, не «ещё один абзац в skill».

open("http://localhost:9821/login");   // 03-env

23 · login · rag

RAG: факты с полки, не догадки 7b

Skill говорит «прочитай 2–4 чанка». Без RAG модель выдумывает $("input") и копирует happy path. С RAG — data-testid, submitExpectingError, текст ошибки, стенды.

без чанков · «на глаз»

// в LoginTests.java
$("#login").setValue("user1");
$("#pass").setValue("123");
$(".btn-primary").click();
$(".alert").shouldHave(text("Invalid"));

// или с вкладки happy path:
fillAndSubmitForm("user1", "wrongpassword")
  .shouldHaveWelcomeMessage("…");  // ждёт HomePage

@Step("Type password: {password}")
@Step() на классе LoginPage

skill назвал чанки · агент их прочитал

po-locators   LoginPage:
  $("[data-testid='login-input']")
  $("[data-testid='error-message']")

po-step       @Step на методах, не на классе
              Type password  // не {password}

test-negative typeUsername → typePassword
              → submitExpectingError
              «Wrong login or password»

cfg-stands    URL из config; user1 есть на
              pipeline / stage / prod
              (wrong password сид не сносит)
Не RAGСкармливать всю папку rag/. «Прочитай стеллаж» → 7b тонет. Task testE2e — это rule 01, не карточка факта.

ADR 009: 401 — не новый e2e

Skill+RAG умеют как кликнуть. ADR фиксирует почему A, не B, иначе каждый чат снова закрывает JSON браузером.

без ADR · «на всякий e2e»

// ещё один браузерный тест «на 401»
open("/login"); fill; submit;
$("pre").shouldHave(text("401"));   // нет такого UI

class Login401Tests { … }           // второй файл
// AuthApiTests#loginWithInvalidPassword
// уже лежит в репо — не открыли ADR

с ADR 009 · развилка закрыта

Контракт 401 JSON
  AuthApiTests#loginWithInvalidPassword
  @Layer("api")  ← RAG test-api-layer

Текст ошибки на форме
  LoginTests#shouldShowErrorWhenPasswordIsWrong
  @Layer("e2e")  ← живой /api, не ярус ui
  // ui = LoginFormTests / HeaderTests на mock

Не $("pre") «401» — нет такого UI
Не ADR«В этом тесте опечатка в тексте ошибки» — поправь константу. «Поставь JDK 21» — RAG/rule. Не писать ADR на каждый новый метод LoginTests.
Это ADR401 не закрываем кликом, если нет UI-состояния. Факт селектора остаётся RAG, не копируется в ADR. Screenshot = slice — другой промпт, ADR 005, лист 04.

Пятая опция: сцена, не скрипт

Project context — открытые вкладки, индекс репо, TestBase, build.gradle. Его включают всегда (лист 30). Это не пятый слой: он не отвечает ни на «как», ни на «нельзя», ни на «факт», ни на «почему».

Что такое Contextсцена
  • Вкладки: LoginTests, LoginPage
  • Недавно открытый TestBase
  • Поиск по репо / @codebase
  • Сигнатуры Gradle, если агент дошёл

Примеры «как уже сделано». Нет When, нет запрета, нет точного текста ошибки, нет развилки 401.

Чего Context не делаетне слой
  • Не skill — не заставляет выбрать один @Layer и DoD
  • Не rule — не держит «не commit» на следующем ходе
  • Не RAG — happy path на вкладке ≠ error path
  • Не ADR — не помнит, почему 401 не кликают
